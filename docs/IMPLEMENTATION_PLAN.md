# Milestones and acceptance gates

**Live observation smoke test, 2026-11-24:** Launched the installed Steam game after save/PlayerPrefs backup. Verified the loopback listener belonged to the NEONSKY process. The Python client received `MainMenu` status at frame 41 and captured frame 66 at time scale 1. Pillow decoded the 1176x664 PNG; its RGB channels were nonuniform. Local artifact: `logs\smoke\live-frame.png`. This verifies the read-only game-to-Python path only; no actions, resets, death or completion events were tested.

**Live control smoke test, same build:** Entered New Game with no `save.json`, invoked the only enabled level, and observed `Cutscene_1 -> Cutscene_1_2 -> Level_1`. The active controller was the ship, not Rick. Two fresh reloads produced distinct scene handles and the same starting XY. A 12-tick right action moved X from -0.2125 to 1.1075; 12 ticks left returned it to -0.2125. Natural death incremented the death counter, disabled the ship and reached game-over; restarting returned a live ship and the original XY. Repeated via `python -m python.tests.live_ship`, including PNG decoding. Evidence: `logs\smoke\live-ship-trace.json` and `logs\smoke\20261124-032924\trace.jsonl`. Not verified: completion, on-foot controls, deterministic stepping, or learning.

1. **Host and game.** Inventory and assembly inspection are recorded in ARCHITECTURE. Build the loader plugin against the local game; keep generated files and dependencies out of Git. Confirm GPU execution with a tensor operation, not driver version alone.
2. **Real bridge.** First capture PNG and metadata from the live player. Identify a reachable on-foot level and record its scene name and initialized controller. Add session authentication before control. Inject bound-key state only in Rick's input path, with one jump edge per press and neutral on disconnect. Latch confirmed death and completion, reload through the verified game path and wait for initialized scene/player. Compare screenshots and initial state across repeated resets. Test movement in both directions, simultaneous jump, death, completion, pause, focus loss, disconnection and restart. Do not report success from static IL alone.
3. **Gymnasium.** Implemented and exercised the three-action ship environment. Run `logs\random\1795483944273409600`: seeds 100-104, 102 decisions, five natural deaths, zero completions, identical observed start positions. A separate seed-105 two-step cap returned truncated, not terminated. A deliberately delayed action after death returned a terminal PNG, zero applied ticks and reward -1. Applied input covered 398 of 567 elapsed fixed updates: the remaining 169 ticks advanced between or around decisions. This is a real-time control smoke test, not a deterministic benchmark. Platformer six-way controls, checkpoint and validated progress rewards remain gated on a reachable on-foot level.
4. **Control condition.** Pin compatible Gymnasium/SB3 after the real environment works. CNN PPO; checkpoints, resume, TensorBoard and fixed-budget held-out evaluation against random across multiple seeds. Report throughput, completion, return, progress and confidence intervals.
5. **Connectome prototype.** Review actual source, releases, datasets and licenses of nfly, flyvis and FlyWire before choosing. Document measured topology vs inferred/assumed parameters, subset selection and visual mapping. Verify edge direction, IDs and sparse aggregation against source records. Start with a fixed recurrent reservoir and train a small readout. Reset neural state at episode boundaries.
6. **Biological comparisons.** Benchmark frozen topology vs training weights only on existing edges. Measure gradient stability, memory, wall time, inference latency and learning curves. Reward-modulated plasticity is a distinct hypothesis, not a substitute for PPO.
7. **Scale only with evidence.** Measure sparse graph/activation/optimizer storage and truncated recurrent training on smaller real subnetworks. Profile environment and GPU separately; optimize after observation. Full-brain feasibility, speedup and successful learning are open questions.
