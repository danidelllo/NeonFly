## Game-specific findings (static inspection, not runtime tests)

| Path | Evidence and implication |
|---|---|
| Platformer | `RickController.Update` reads configured `SettingsData.rickLeft`, `rickRight`, and edge-triggered `rickJump` via legacy `UnityEngine.Input`. `FixedUpdate` applies horizontal motion and buffered grounded jumps through `Rigidbody2D`. Scope the six-action experiment to scenes containing this controller. Do not move transforms or treat a ship scene as a failed platformer episode. |
| Ship | `Player.GetHorizontalInput` / `GetVerticalInput` read separate ship bindings, and `Player.HandleMovement` writes velocity. Its vertical input is **not** jump. |
| Death | `RickController.RickDying` sets a death flag; `TriggerGameOver` calls `GameSessionManager.GameOver` later. `DeathZone.OnTriggerEnter2D` can damage health; trigger entry alone is not proof of death. Verify latching exactly one terminal event. |
| Completion | `LevelEndTrigger.OnTriggerEnter2D` checks the Player tag and `triggered`, saves progress, and initiates a transition. A generic collision or scene transition is not itself completion. Completion can affect saves and achievements. |
| Reset | `GameSessionManager.Play` contains current-scene reloads. `RickController.Start` loads saved progress, so reloading alone does not prove an identical starting state. Test with isolated save state before training. |
| Pause and rendering | `PauseManager` toggles UI and time scale. Capture the final composited player frame at `WaitForEndOfFrame`, not a guessed camera. A zero time scale is diagnostic, not a definitive pause/loading classifier. Checkpoints, loading, background rendering and deterministic stepping are not verified. |

## Observation bridge v1

The read-only scene scan (`scripts\inspect_scenes.py`, UnityPy 1.25.2) found direct serialized `RickController` references in **Level_4_1, Level_4_2, Level_4_3, Level_4_7 and Level_4_8** (indices 27, 29, 31, 40 and 42). All five also referenced the ship controller, end trigger, pause and game-session managers. Component presence is not evidence of an active controller or an unlocked level. Target Level_4_1 first if accessible through normal game progression.

Unity main thread: capture status or a screenshot at end of frame. Worker thread: blocking TCP I/O on loopback only. Single outstanding operation, one client serviced at a time, backlog one, finite I/O and render waits. API is read-only; no game-specific method is patched yet. One TCP connection per request. Request: ASCII `NFL1`, followed by one opcode byte (`1` status, `2` PNG). Response: `NFL1`, little-endian uint32 UTF-8 JSON length, little-endian uint32 image length, JSON, optional raw PNG bytes. Errors have `ok:false` and an error code. Unsupported opcodes are rejected; a disconnected stream must not be reused as a transition. Limits: 64 KiB metadata at receiver, 32 MiB image, 16,777,216 capture pixels. Loopback alone does not authenticate other local processes; do not enable controls or use in an untrusted multi-user session without session authentication.

### Installed adapter 0.2

The v1 status and screenshot framing above remains compatible. Additional authenticated requests append the 32 raw bytes from `%LOCALAPPDATA%\NeonFly\session.key` after the opcode; this per-launch key is stored outside the repo in the current user's profile. Do not copy it into traces. Control ops: `3` invoke the active NewGame button **only if no save file exists** (the game itself clears PlayerPrefs); `4` invoke the enabled first-level button in LevelSelect; `5` ship horizontal step (two further bytes: direction 0/1/2 = left/neutral/right, then duration 1..32 fixed updates); `6` restart current gameplay scene through GameSessionManager.Play. Menu and reset responses wait for a changed scene handle. Step/reset include PNG. A failed or ambiguous request must not be retried automatically.

Scoped Harmony patches substitute the ship's horizontal input result and count completed Player.FixedUpdate calls; no teleportation or game-wide input patch. Status distinguishes active controller, game-over, process-wide ship death and completion counters, and diagnostic position (invalid when controller is none). Death was observed live; completion latching was implemented but not live-tested. The game continues advancing between calls; elapsed simulation time is **not** limited to action duration. This adapter does not implement a deterministic Gymnasium environment or on-foot jumping.

## Planned data flow

The active ship policy uses plugin 0.4 and guarded opcode 8. The earlier horizontal-only interfaces remain available for regression tests. See [the controls audit and wire mapping](CONTROLS.md) for the complete ship action space and distinct on-foot semantics.

**Gymnasium ship adapter 0.3:** Authenticated opcode 7 extends opcode 5 with three little-endian signed int32s from reset: scene handle, death count, completion count. Unity checks these on the main thread before applying input. A new terminal event returns an image with zero applied ticks if it preceded action dispatch. No action is replayed on transport failure. Responses expose a process-wide fixed-update counter so the client can distinguish real elapsed ticks from acknowledged input duration. Unexpected scene changes, incomplete nonterminal actions and lost connections invalidate the episode. Reconnect via a fresh explicit reset after returning to Level_1; the wrapper never launches the game or fabricates a transition. Seeds control action sampling, not Unity randomness.

The initial **ship-only** reward counts acknowledged input ticks plus one-shot death/completion terms. It is a timing-dependent survival proxy, not verified level progress. Neither ship X nor screen motion is treated as course completion; movement back and forth earns no positional bonus. Discount comparisons across agents with different inference latency are unsafe until the control gap is addressed.

Game adapter -> synchronized capture + event metadata -> transport -> Gymnasium. The environment separates pixel observations from reward/diagnostic state. The shared visual pipeline resizes to 84x84 and stacks frames. An action must be acknowledged at a defined input/physics boundary; the passive bridge does not promise that the world freezes between requests. Record actual elapsed ticks and reject invalid transitions. Keep the initial time scale unchanged.

Random policy and CNN PPO validate the environment first. Compare a fly-inspired control and a genuine connectome reservoir under the same reward and evaluation protocol. Preserve immutable source neuron IDs, directed edges and synapse counts; keep inferred signs, assumed dynamics, artificial retinotopic encoder, action readout and PPO learning rule separate. No dense full-brain adjacency or unverified pixel-to-neuron assignments.
